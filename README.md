# User & Project Management REST API

A layered ASP.NET Core .NET 10 Web API for JWT-authenticated user and project management. It uses Entity Framework Core with SQL Server, role-based authorization, soft deletes, pagination, rate limiting, and centralized exception handling.

## Setup

1. Install the .NET 10 SDK and SQL Server LocalDB.
2. Update `ConnectionStrings:DefaultConnection` in `appsettings.Development.json`.
3. Replace `Jwt:Secret` with a long random secret for any non-local environment.
4. Run the API:

```powershell
dotnet restore
dotnet run
```

The application creates the database on first startup and seeds these development accounts:

| Email | Password | Role |
| --- | --- | --- |
| admin@example.com | ChangeMe123! | Admin |
| user@example.com | ChangeMe123! | User |

Change or remove seeded credentials before deployment. For production, use EF Core migrations instead of `EnsureCreated` and store secrets outside source control.

Swagger UI is available at `/swagger`.

## API endpoints

All routes are versioned under `/api/v1`.

- `POST /auth/login` - authenticate and receive a JWT.
- `GET /users?page=1&pageSize=20&search=term` - admin-only paged user list.
- `POST /users` - admin-only user creation.
- `PUT /users/{id}` - admin-only user update.
- `DELETE /users/{id}` - admin-only soft delete.
- `GET /projects?page=1&pageSize=20&status=Active` - authenticated project list.
- `POST /projects` - create a project as the current user.
- `PUT /projects/{id}` - update a project.
- `POST /projects/{id}/members` - assign an active user to a project.

Project statuses are `Active`, `OnHold`, and `Completed`.

## Example requests

```http
POST /api/v1/auth/login
Content-Type: application/json

{"email":"admin@example.com","password":"ChangeMe123!"}
```

Use the returned token as `Authorization: Bearer <token>`.

```http
POST /api/v1/projects
Authorization: Bearer <token>
Content-Type: application/json

{"name":"Website Refresh","description":"New public site","status":"Active"}
```

## Architecture

- `Domain` contains entities and enums with no infrastructure concerns.
- `Application` contains DTOs, contracts, and service-layer business logic.
- `Infrastructure` contains EF Core persistence, indexes, seeding, and exception middleware.
- `Controllers` exposes versioned HTTP endpoints and authorization boundaries.

Read queries use `AsNoTracking`, project members are loaded with a single include graph to avoid N+1 queries, and SQL parameters are generated by EF Core. Users are soft deleted and excluded from authentication and listings.

## Security notes

JWT issuer, audience, expiration, and signing secret are configuration-driven. Passwords are hashed using BCrypt. The `AdminOnly` policy protects user management. A fixed-window rate limiter allows 100 requests per minute per application policy. Add distributed rate limiting, secret management, HTTPS enforcement, audit logging, and database migrations for production use.
